Something changed at 3am and nobody remembers doing it. ClusterTrail answers the question your monitoring cannot: what changed, who changed it, what has drifted from Git. And it refuses to apply anything nobody approved.

Try it in your browser Read the source ./clustertrail serve --open

The demo is the real interface on a real cluster, recorded. One binary to run it on yours: no installer, no Node, nothing in your cluster.

Four questions, answered in one place

What changed in the last hour?

Rollouts with the image that actually moved, the fields people edited, cluster events, and every change you approved, merged into one ordered list. The actor comes from managedFields, which Kubernetes writes on every object and almost nothing surfaces.

Tick People only and a hundred lines become three.

What has drifted from Git?

Point it at the directory your cluster is deployed from. You get what is in Git but not running, what differs, and what is running with no file behind it. Plain YAML, Kustomize overlays and Helm charts all render.

The same check runs in CI and exits non-zero on drift.

Who approved this?

Every write is proposed first: a real diff from a server-side dry run, the blast radius, then a human decision. Each step lands in an append-only log where every entry carries the fingerprint of the one before it.

Scale, restart, delete, edit, roll back. Same gate.

Can AI help without breaking anything?

There is an explain pane, and an MCP server your coding agent can read clusters through. Neither can write. The tools that change a cluster are not in the interface the model sees, so there is nothing to switch off and nothing to trust the model about.

That is the version a security team approves.

It is also the client you keep open

A tool you do not use daily cannot be the one that catches the change nobody remembers making. So it does the ordinary job properly: every workload kind plus custom resources, live tables, logs that follow, a terminal, port forwards, a YAML editor.

Tables paint from cache in about eight milliseconds, before any cluster has answered, then refresh. Charts come from metrics-server, so you get CPU and memory history without running Prometheus.

Nothing lands without a diff

The dialog says what will happen in a sentence, what it touches, and shows the exact diff, taken by asking your API server what it would store rather than by comparing text. Defaulted fields and admission webhooks are already accounted for.

Approve, or press escape. Either way it is written down, with your name on it.

Install

Download one file and run it. It reads the kubeconfig you already have and opens your browser.

1

Download

Take the build for your machine from the releases page. macOS, Linux and Windows, Intel and ARM.

2

Run it

chmod +x clustertrail-*
./clustertrail-* serve --open
3

That is it

No installer, no daemon, nothing added to your clusters. Close the terminal to stop it.

The binaries are not code-signed yet, so macOS and Windows will warn you the first time. On macOS: System Settings, Privacy & Security, Open Anyway. On Windows: More info, then Run anyway. Linux just runs it.

For your pipeline

# fails the build when the cluster and the repository disagree
clustertrail drift --repo deploy --unmanaged

For your coding agent

claude mcp add clustertrail -- /path/to/clustertrail mcp

What it can and cannot do

It can see exactly what you can

ClusterTrail authenticates as you, with the kubeconfig you already use, including the sign-in plugins for EKS, GKE and AKS. It installs no agent, no operator and no custom resource. If your account cannot read Secrets in a namespace, neither can it. The review is the one you already did for kubectl.

Nothing leaves your machine

The engine listens on loopback only, on a random port, behind a token that changes every launch, and it checks that each request was actually addressed to it. The one exception is the explain pane, which stays inert until a model key is available, and which shows you the exact bytes and waits for you to press send. Secret values are replaced before you see them.

Nothing connects until you ask

Every context in your kubeconfig is listed, but none is contacted until you select it. Starting the app never triggers a cloud sign-in prompt you did not ask for.

The record resists quiet edits

Each audit entry carries the hash of the entry before it, so removing or rewriting one breaks the chain and can be detected. That is tamper evidence, not tamper proofing, and the difference is documented rather than glossed over.

Where it is

Built and working

  • Twenty-one resource kinds, plus any custom resource, using the columns its CRD declares
  • The What changed timeline, from four sources at once
  • Drift against plain YAML, Kustomize and Helm charts, on screen and in CI
  • Capture what drifted into a branch, and open the pull request
  • The change gate, with dry-run diffs and a hash-chained audit log
  • Helm releases read straight from the cluster, with rollback
  • A read-only MCP server, and an explain pane with your own key
  • One self-contained binary that serves its own interface

Pending

  • A desktop shell. It runs in your browser today. The shell adds a dock icon, the keychain and auto-update, and changes nothing else.

Deliberately later

  • The relay, phone approvals, and an agent that proposes changes into the same review queue. These wait until teams commit to paying for them.
